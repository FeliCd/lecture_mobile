## Security review

- No hardcoded secrets, Google passwords, direct DB credentials, FAP tokens/cookies or authorization scraping.
- Only the configured HTTPS Apps Script endpoint receives the ID token, in the POST body; a validated Google ContentService redirect uses an empty GET and disallows further redirects.
- Backend remains authoritative for identity, lecturer registration, ownership, enrollment, duplicate prevention and mutation permissions. Client guards are defense in depth.
- Token is stored with flutter_secure_storage; Android backups disabled; iOS Keychain entitlements included. Native device behavior remains to be checked.
- Error strings are mapped to safe user messages, never rendered raw; production code does not print credentials or payloads.
- No local attendance persistence or offline replay queue. No automatic ambiguous write retry.
- Private Navigator tree is replaced on logout. Secure deletion failures are visible and retryable.
- Release signing is explicit; a missing release key file fails the build rather than using a debug key.
- Backend concerns are documented in REFERENCE_AUDIT.md and were not altered.

## Final acceptance boundaries

The standalone source, independent Android build, compatible contracts, mobile flows, API configuration, secure-storage integration, README, test suite and reference isolation can be verified locally. Production readiness still requires mobile OAuth audience compatibility, native-device login/storage tests, real API/QR acceptance, production signing, and an iOS build on macOS. Remote Excel, notifications and unsupported schedule/rate metadata are intentionally pending.
